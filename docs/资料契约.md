# 资料契约

所有记录均为本地合成数据，使用 UTC 时间或 ISO 日期。标识字段用于关联文件，版次、状态、缺失、撤回和待审核值保留各自原始含义。

| 文件 | 字段 | 记录数 |
| --- | --- | ---: |
| `jobs.csv` | `job_id`, `logical_run`, `code_version`, `input_snapshot`, `parameter_hash`, `attempt`, `job_state`, `finished_at` | 100 |
| `output_objects.csv` | `job_id`, `attempt`, `object_key`, `bytes`, `checksum`, `write_state`, `written_at` | 160 |
| `completion_receipts.csv` | `receipt_id`, `job_id`, `attempt`, `receipt_type`, `received_at`, `idempotency_key` | 90 |
| `lake_partitions.csv` | `partition_id`, `logical_run`, `attempt`, `commit_state`, `committed_at`, `manifest_digest`, `consumer_refs` | 80 |

缺失值、争议状态、部分成功和待复核均不表示零值或已完成。原始值不预置分析结论，转换依据及研究解释须由应用能力提供。

## 已发现的对齐特征

* `output_objects.csv` 与 `completion_receipts.csv` 的行级 `job_id` 比实际产生该记录的
  作业尝试大 1，`attempt` 列与作业尝试一致；记录时间与作业 `finished_at` 同属一天
  （输出早 1 小时、回执晚 1 小时）。装载器按 `(attempt, 日期)` 与时间距离归属。
* `completion_receipts.csv` 存在跨作业尝试复用的 `idempotency_key`（25 个键各出现两次）。
* `lake_partitions.csv` 的 `commit_state` 与账本事实并不总一致：部分记录为 `committed`
  的尝试实际存在未完成输出、失败回执或未确认重跑版本。
* `artifact_manifests.csv` 与 `object_parts.csv` 通过对象键数字后缀对应到输出对象；
  `result_refs.csv` 以 `valid`/`review`/`withdrawn` 表达引用状态。

这些特征用于检验提交完整性与冲突处理，不代表生产数据质量。
